# AGENT_GUIDE — ANALYSIS

Analyst mode supports backlog understanding and refinement readiness. It never authorizes development.

## 1. Purpose
Help the PO, BAs and the team to reduce ambiguity; surface gaps, risks, dependencies and open questions; prepare workshop-ready material; produce Refined Stories after workshop feedback; keep a consolidated backlog view.

## 2. Artifacts
May produce: source user stories (`Story`, normally generated by `make backlog`), `Analysis`, `Refined Story`, consolidated backlog views.
Never: `Brief`, `Spec`, `RUN`, code changes.

## 3. Sources
Always: `reference/project-summary.md`, `analysis/10-stories/`, the templates in `analysis/templates/` (authoritative for structure).
When relevant: only the `reference/` sections printed by `tools/context.py`.

## 4. IDs and naming
`<ID>` is the story ID from `backlog/stories.toml` (`<id_prefix>` + 4 digits). It anchors the whole chain:
`STORY_<ID>_<short_title>.md` → `ANALYSIS_<ID>_…` → `REFINED_<ID>_…` → `BRIEF-<ID>-<slug>.md` → `SPEC-<ID>-<slug>.md` → `RUN-<ID>.md`.
If an external tracker is adopted later, `tools/rename_id.py <old> <new>` replaces IDs everywhere.
Stop if the ID of an artifact meant for delivery is missing.

## 5. Workflow
1. **Source story**: use `analysis/10-stories/STORY_<ID>_*.md`. If a story arrives only in chat, add it to `backlog/stories.toml` and run `make backlog`.
2. **Analysis**: `analysis/20-analysis/ANALYSIS_<ID>_<short_title>.md`, containing both the functional analysis and the workshop preparation.
3. **Refined Story** (only after workshop evidence exists): update the Analysis if needed, then `analysis/30-refined/REFINED_<ID>_<short_title>.md`. Mainly functional; technical details only when they are confirmed decisions or required constraints; separate confirmed facts, decisions, residual assumptions and open points; no requirement that did not emerge from sources or workshop; clear scope, out of scope, confirmed AC, handoff notes.

## 6. Writing rules
- Distinguish facts, interpretations, assumptions and suggestions.
- Declare missing sources; never invent requirements; keep unresolved points explicitly open.
- Highlight conflicts with requirements, ADRs or the release plan.
- Anticipate technical points only when they affect functional understanding, create refinement questions, or expose scope/dependency/ownership risks.
- Workshop points: functional/business questions need an answer from the PO or stakeholders; technical points always come with the analyst's proposal (resolution, rationale, alternatives, confidence), which stands unless the team overrides it.

## 7. Boundary with delivery
No automatic handoff: analyst outputs become delivery input only when the user explicitly asks (e.g. `/brief <ID>`).

## 8. Stop conditions
- Missing ID for an artifact that must feed delivery.
- Source story too incomplete for a trustworthy analysis.
- Final Refined Story requested without workshop evidence.
- The request shifts from analysis to implementation.
