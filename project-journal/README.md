# Project Journal

> The organizational memory of the project.

Every project produces more than software: decisions, hypotheses, changes of direction, learnings, solved problems, ways of working. The Journal turns them into shared memory, and is an observatory on how people, process and AI agents interact along the value stream.

## Who reads it
- **Team**: a shared view of decisions, issues and learnings.
- **Management**: progress and decisions to support.
- **Researchers / stakeholders**: systematic evidence on the agent-supervised model.

## Manifesto
1. **Memory, not archive**: it keeps what the project must remember — decisions, observations, learnings, metrics, context.
2. **Consolidates, does not duplicate**: operational information stays in the team's tools.
3. **Tells the evolution**: what changed, why, which decisions, which effects, which learnings.
4. **History is not rewritten**: new entries are appended; old ones stay as recorded.
5. **Facts before interpretations**: facts, interpretations, decisions and learnings are kept distinct.
6. **Owned by the team**: AI helps collect and organize; people own the content.

## Structure
| Section | Content |
|---|---|
| `context/` | Vision, starting hypotheses, organization, working model. Stable. |
| `weekly/` | Evidence of the week, base for weekly / steering meetings. |
| `monthly/` | Cross-reading: patterns, learnings, value stream, agent-supervised model, business case. |
| `notes/` | Temporary raw material (minutes, workshop notes) to consolidate. `current-week.md` collects quick notes. |
| `decisions/`, `learnings/`, `risks/`, `metrics/` | Optional detailed registers, used only when needed. |
| `templates/` | Templates for all of the above. |

Flow: notes / transcripts / minutes → **Weekly** → **Monthly**.

Quality: accurate, verifiable, concise, contextualized, consistent with the glossary, linked when useful.
